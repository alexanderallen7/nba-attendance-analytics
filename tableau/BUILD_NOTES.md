# Tableau workbook build notes

The workbook `tableau/nba_attendance_dashboard.twb` was generated by
`scripts/extend_workbook.py` from a hand-saved seed workbook. This file
explains every calculated field, the parameter, and the table
calculation in plain language — written so each one can be explained in
an interview — and lists the few finishing steps done by hand in
Tableau.

## Data connection

The workbook connects live to `data/processed/extract.csv` (one row per
regular-season game, 2013-14 through 2022-23). When Tableau Public
publishes it, it converts the connection to an extract automatically.

## The parameter

**Select Team** (`Parameter 1`) — a string parameter listing all 30 team
abbreviations (displayed as full team names), defaulting to **HOU**.
A parameter is a single global value the viewer controls; every
calculated field that mentions it re-evaluates when it changes. That is
what makes the dashboard "about" whichever team is selected without
filtering any data away.

## Calculated fields

- **Fill Rate (calc)** = `[attendance] / [capacity]`
  Row-level ratio of reported attendance to listed capacity. The extract
  already carries a capped `fill_rate` column computed in SQL; this
  field demonstrates the same logic in Tableau. Not used on the
  dashboard sheets (the SQL column is authoritative because it applies
  the documented 1.0 cap).

- **Included Fill Rate** = `IF [excluded_flag] = 0 THEN [fill_rate] END`
  The workhorse measure. Returns the capped fill rate for analysis-ready
  games and NULL for excluded ones (COVID bubble, 2020-21 season,
  international and alternate-venue games). Tableau's AVG ignores NULLs,
  so every view built on this field automatically respects the
  exclusion rules from the SQL pipeline — no view-level filters needed.

- **Team Avg Fill Rate (LOD)** =
  `{ FIXED [home_team] : AVG([Included Fill Rate]) }`
  A FIXED level-of-detail expression: computes each team's average fill
  rate at exactly the home-team level, regardless of what dimensions are
  in the view or what filters are applied. Interview framing: "FIXED
  pins the aggregation level, so I can compare a game's fill to the
  team's overall average inside a single row-level view."

- **Sellout % (included games)** =
  `AVG(IF [excluded_flag] = 0 THEN [sellout_flag] END)`
  The share of non-excluded games where reported attendance reached
  listed capacity. Averaging a 0/1 flag gives a proportion.

- **League Avg Fill Rate** = `AVG([Included Fill Rate])`
  League-wide average at whatever level the view slices (overall on the
  KPI tile, per season on the trend sheet).

- **Selected Team Fill Rate** =
  `AVG(IF [home_team] = [Parameter].[Select Team] THEN [Included Fill Rate] END)`
  Same average restricted to the parameter team, computed as a
  conditional aggregate rather than a filter so it can sit next to the
  league number in the same view.

- **Selected Team Sellout %** — same pattern for the sellout flag.

- **Team vs League** =
  `IF [home_team] = [Select Team] THEN "Selected team" ELSE "Other teams" END`
  A two-value dimension used on Color, so the selected team is
  highlighted (red) against gray everywhere without filtering.

- **Fill Rate YoY % (table calc)** =
  `AVG([Included Fill Rate]) / LOOKUP(AVG([Included Fill Rate]), -1) - 1`
  A table calculation: LOOKUP(…, -1) reaches back to the previous
  season's cell in the view, so the field computes season-over-season
  percent change. Table calcs run on the aggregated view results (after
  the query), which is why the field only makes sense with Season in the
  view and "Compute Using: Table (across)". Shown on its own sheet
  ("Fill Rate YoY Change"), which **filters out 2020-21**: that season
  has no included games, so without the filter it would chart a
  misleading −100% (and deliberately no `ZN()` wrapper, which would
  coerce that null to 0). With the filter, LOOKUP(-1) makes the 2021-22
  bar a change vs 2019-20, which the sheet title states. Interview
  framing: "table calcs operate on the cells the view shows, so
  filtering a season changes what 'previous' means — I used that
  deliberately and labeled it."

## Sheets

1. **KPI League Fill Rate / KPI Selected Team Fill Rate / KPI Selected
   Team Sellout Pct** — single-number text tiles for the dashboard header.
2. **Fill Rate by Team** — bar chart of average included fill rate per
   home team, sorted descending, selected team highlighted.
3. **Fill Rate by Season** — line chart by season, selected team vs all
   other teams. 2020-21 is absent by construction (every game excluded);
   the title says so instead of pretending the line is continuous.
4. **Weekday Month Heatmap** — day-of-week (Mon→Sun) by month
   (Oct→Apr, season order) grid colored by average fill rate, with the
   percentage printed in each cell.
5. **Win Pct vs Fill Rate** — scatter of team-season points: average
   entering win percentage vs average fill rate.
6. **Fill Rate YoY Change** — the table-calc bar chart (workbook only,
   not on the dashboard).

## Dashboard

**NBA Home Attendance** — fixed 1100 × 900 (a size Tableau Public
renders without scrollbars on most laptops): title, KPI row with the
parameter control, four analytical views in a 2×2 grid, and a
"How to read this" footer defining every metric (fill rate, sellout,
entering win %, exclusions, team-reported attendance caveat).

## Finishing steps done by hand in Tableau

These are interactive behaviors that are not reliable to author as raw
XML, so they were added through the UI after generation (click-by-click
steps are in the chat log / README):

1. **Parameter action** — Dashboard ▸ Actions ▸ Add Action ▸ Change
   Parameter: source "Fill Rate by Team", target parameter "Select
   Team", field `home_team`, run on Select. Clicking a team's bar then
   drives the whole dashboard.
2. **Season filter** — on "Fill Rate by Team": drag `season` to
   Filters, show the filter card, set it to apply to all sheets using
   this data source, then add it to the dashboard.
3. **Trend line on the scatter** — Analytics pane ▸ drag Trend Line
   onto the view (linear).
4. **Formatting checks** — confirm the fill-rate axes/labels display as
   percentages (the generated fields carry a percent default format;
   if any show as decimals: right-click field ▸ Default Properties ▸
   Number Format ▸ Percentage, 1 decimal).
